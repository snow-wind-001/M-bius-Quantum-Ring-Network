# 追加旧回放节奏对照

2026-10-20，在正式六方法矩阵运行中、完整结果尚未生成时追加。该对照不改变 `go12_plan.md` 的原始六组协议，不重选其参数或种子。

增加它的原因是实现审计：主析因对照把终局回放批次统一为 64，短信用组在批内每 16 步截断，以匹配更新次数。但 Go11 旧实现每 16 步就进行一次终局参数更新。原六组可以检验辅助监督和信用效应，却不足以直接声称新回放节奏优于旧实现。

`legacy` 使用与 Go12 相同的五个预训练检查点、36,212 参数（辅助头存在但权重零）、16 局双方在线训练、16 模拟/8 深度搜索、48 局/种子冻结评估、相同开局和四个保护锚点。唯一方案区别是终局 `replay_window=16`，信用仍为 16；没有 4/8 局中间评估。主矩阵 baseline 的终局窗口为 64。

按现有代码计算，长度为 T 的同一棋谱，legacy 更新数为 \(2\lceil T/16\rceil\)，baseline 为 \(\lceil T/16\rceil+\lceil T/64\rceil\)。总反馈量相同，优化次数不同；它是旧更新节奏的实际基线，不是等优化次数的信用消融。

运行器是 `experiments/go12_legacy_control.py`：在独立进程中显式替换会话工厂与来源记录，复用未经修改的 Go12 运行循环，并将适配器自身纳入 SHA256。所有原矩阵进程不受影响。相同底座文件逐字节核对。

追加 5×16=80 局训练与 5×48=240 局评估，共 320 局。加上主协议与公共基础数据，当前完整证据计划为 **2780 局**，不把重复恢复验证或劫诊断算成新增棋局。
